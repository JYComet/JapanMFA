# 0922jap：Qwen 原文与分词假名输入对齐对照（2026-09-28）

## 方法

使用 `/mnt/Raw/0922jap` 的七条 OGG/TXT，经主管线生成的同一份 16 kHz 工作 WAV（`runs/0922jap-context-fix-curated-20260928/<样本>/work/audio.wav`）。每条 WAV 分别以原文、主管线分词后锁定读音拼接的假名文本，调用一次原生 `Qwen3-ForcedAligner-0.6B.align(audio, text, language="Japanese")`。两个条件仅改变传入的文本。假名保留原标点；0050、0070、0100、0110 使用 `configs/0922jap-reading-overrides.yaml` 已审核的逐词读音覆盖。七条的 37 个分词读音均与已通过 MFA G2P 的 occurrence-alias 数据逐项一致。G2P 把假名变成音素，并非负责产生假名；假名由 Sudachi 分词读音与覆盖项形成。

模型为项目 `.runtime/models/qwen3-forced-aligner-0.6b` 的原生检查点，权重 SHA-256 `47831d0e82f96b20e9034dba01a075ee06436654719f6a68289e49f1b65ce0e7`。使用 `.runtime/envs/asr/bin/python3.10`、`qwen-asr 0.0.6`、RTX 4090 D、BF16。一次加载模型，原文和假名分别按最多四条音频批量推理。原始输出、音频哈希、每词读音、模型调用脚本和分析脚本保存在 `.runtime/artifacts/qwen-original-kana-0922jap-20260928/`。脚本可依次运行：

```bash
.runtime/envs/asr/bin/python3.10 .runtime/artifacts/qwen-original-kana-0922jap-20260928/compare.py
python .runtime/artifacts/qwen-original-kana-0922jap-20260928/analyze.py
```

## 判断

在这七条游戏语音、当前分词与读音配置下，**原文更适合作为 Qwen ForcedAligner 的输入**：它明显保留了更多可用于逐词时间轴的边界；假名并没有稳定改善时间定位，反而在 0070、0090 等样本产生词合并、零时长或明显错位。原文也有错误，特别是 0050、0100、0110，不能把“原文更好”解释为原文时间戳可直接作为音素金标。

此语料没有人工标注的逐词起止时间，因此不能计算两种文本输入的真正平均绝对边界误差。RMS 只是对 0090 等明显错位提供独立声学线索，不是语音分类器；BGM 也会抬高能量。正式发表或自动发布仍应结合 MFA、声学覆盖检查和人工复核。不同模型版本、分词器、读音写法或语料可能改变比较结果。
