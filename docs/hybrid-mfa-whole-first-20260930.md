# 整段优先、完整 WAV 加 CTC 锚点回退的批量 MFA 方案

目标：对同一批预先给出 WAV/TXT/CTC 的音频，一次 MFA 调用预生成完整 WAV 的整段候选和带 CTC `speaker` 窗口的候选；先逐条审查整段，只有整段未通过且诊断表明边界/时间戳错位，才读取同次运行的锚点候选。窗口候选仍须经过相同检查。任何候选未通过时保留筛选，不以 CTC 接近程度覆盖声能证据。100 个候选同时进入一个语料会使少量边界随批次改变，必须保留已有合格结果并记录每次的审计差异。

输入准备复用 `JapanMFAPipeline` 现有音频、文本、前端、声调、G2P 与词典步骤，不运行逐段 MFA；准备产物必须包含源 WAV/文本/CTC 哈希、工作 WAV、锁定词别名和带声能扩展的 CTC 分段。跨音频合并词典时给每个词项全局唯一别名，避免不同条目的局部 `jmfa_000000` 冲突；批量结果需按映射恢复每条原别名并校验词序。第二批参考旧项目 `run_pipeline.py::_build_native_anchor_corpus`：原 WAV 保持完整时间轴，CTC 窗口写入语料 TextGrid，不创建裁剪 WAV；当前窗口按已有 CTC 分组，未逐词重建旧项目的最小 110 ms 单词窗口。

完整候选的 CTC 只用于复核，不限制 MFA 输入。回退条件为现有后处理拒绝且原因属于 `timestamp_mfa_disagreement`、`alignment_acoustic_coverage`、`phone_in_silence`、`word_in_silence`；其他前端/模型/输出失败不启动锚点批次。对有声停顿与 CTC 冲突的样本，锚点候选若仍有漏声不得发布。若两候选都失败，分别保留诊断。已通过的完整候选不再重跑。对已有共享合格结果，试验重跑退化时不得覆盖原件。

双候选仍用固定声学模型、锁定词典和 `--dither 1.0`。输入准备已逐项验证文本/词典/WAV 并在批次合并时复核哈希，因此该专用双候选入口只启动一次 `mfa align --clean --no_tokenization --num_jobs 1`，由 MFA 内部建立语料并在输出端严格检查 100 个预期 TextGrid 和词别名；通用 `MfaRunner` 默认仍执行外部 `validate`。单任务模式避免了实测两任务直接对齐时偶发的 SQLite 临时表错误。报告记录总输入数、耗时、实际读取的锚点数、候选选择原因、原始/最终边界与输出哈希。原始 TextGrid 属于诊断证据，只有通过 `postprocess_annotations`、`review_processed_timing`、正式六轨 TextGrid 生成与 `audit_textgrid_pauses.py` 的候选才能作为新成品。逐词 MFA/CTC 融合仅对可按原文字符跨度匹配的词生效，需同时满足 0.15–0.30 s 差异、原 WAV 的安静裁切或连续有声扩展证据、相邻词不重叠以及音素缩放比例 0.75–1.25；零时长和更大错位只保留诊断。

验收：单测覆盖全局词别名隔离、批次 TextGrid 数量/词序校验、整段先运行、未通过才回退、回退候选拒绝不误发布，以及失败证据留存；真实前 50 条作隔离试跑，与当前 39 发布/11 筛选按样本逐项比较，计入完整的阶段耗时。任何批量候选不得因提速而使现有合格 TextGrid 被覆盖。与裁剪 WAV 对照时还必须检查显式静音是否被误写成合成空隙。
