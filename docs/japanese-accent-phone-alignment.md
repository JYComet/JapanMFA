# 日语重音、mora 与音素对齐

JapanMFA 将日语文本中的**读音和重音**对应到音频中的**音素时间区间**。输出可以同时回答三个问题：这段声音对应哪个音素、它属于哪些假名 mora、这些 mora 的预测高低音型是什么。音素边界由 Japanese MFA v3 对音频进行强制对齐得到；重音来自 tdmelodic 的词汇重音预测，不是从音频基频（F0）直接测出的结果。

## 从输入到时间轴

```text
音频 + 原文（有 .txt 时以它为准）
  → Qwen 词语时间信息与日语文本检查
  → Sudachi 分词、锁定每个词的片假名读音
  → 将读音切分为 mora，并用 tdmelodic 标出 H / L
  → MFA G2P 生成音素候选，按 mora 映射规则筛选
  → MFA 对音频定出音素起止时间
  → 将 mora、假名和重音投影到每个真实音素区间
  → 声学与结构检查 → TextGrid、配对音频及诊断 JSON
```

已有 `.txt` 是文本依据；ASR 结果用于校验，不会暗中替换它。没有 `.txt` 时，清理后的日语 ASR 文本需要通过同样的前端检查。Qwen 的词语时间信息用于确定 MFA 的语音片段和核查外边界；片段内部的音素时间由 MFA 给出，而非按文字或 mora 数量平均分配。

## 读音与 mora

Sudachi 为每个发音词提供片假名读音。读音按词出现位置锁定，因此同一字面词出现两次，也可以分别处理读音和音素序列。项目支持按原文位置指定读音覆盖；覆盖仍须经过后续读音和对齐检查。标点保留在原文和最终展示中，不作为发音词送入 MFA。

**Mora（拍）**是重音标注和假名投影的基本单位。例如 `キョウ` 分为 `キョ / ウ`：小写 `ョ` 与前面的 `キ` 组成一拍；`ッ`、`ン`、`ー` 则各自占一拍。一个 mora 可以由多个音素实现，多个 mora 也可以共同对应一个音素。切分要求所有 mora 按顺序重新拼接后恰好等于锁定读音，无法确定的假名组合会明确失败。

## 重音如何得到

每个发音词使用已锁定的表层词形和读音调用 `tdmelodic sy2a(surface, yomi)`。tdmelodic 在读音中使用 `[` 和 `]` 表示 mora 边界处的上升、下降；解析器先去掉标记，再核对读音是否仍与锁定读音完全一致，然后给每个 mora 分配一个 `H`（高）或 `L`（低）。标记不能改变读音，也不能插入到一个完整 mora 的内部。

例如，以下只是说明标记含义的示意，不代表对这个词实际发音的预测：

| 带标记读音 | mora 重音 | 含义 |
| --- | --- | --- |
| `オ]ー` | `オ=H、ー=L` | 在第二拍开始前下降 |
| `オ[ー` | `オ=L、ー=H` | 在第二拍开始前上升 |

词尾的 `]` 可以记录末拍之后的下降，不改变末拍已有的标签；词尾的 `[` 没有后续 mora 可影响，会被拒绝。若标记本身不可用，但去掉标记后的读音仍与锁定读音一致，该词的 mora 可保留为**重音未知**并继续尝试音素对齐；读音不一致则失败。这里的 H/L 是预测的词汇重音状态：清辅音本身未必有可测音高，说话人的语调、情绪或笑声也可能与预测不同。

## mora 如何对应音素

Japanese MFA G2P 为每个锁定读音提供音素候选。项目使用与 **Japanese MFA v3** 模型配套的[片假名与音素规则表](../src/japanmfa/mfa/data/japanese_mfa_v3_phone_map.yaml)，只保留能将该词**全部 mora 和全部音素**按顺序、唯一地对应起来的候选。规则可以声明一个音素对应哪几个 mora；复杂的多对多规则必须写明每个音素的 `mora_spans`，不能靠猜测分配。音素别名只按规则表显式规范化，不会任意删掉长音、清化等 IPA 标记。

MFA 使用每次词出现独有的别名及锁定词典进行对齐。对齐后还会核对词别名顺序与实际音素序列，确保投影用的是 MFA 真正选中的读音。若存在多个同等最优的 mora–音素分组，或出现未知音素、漏拍、错序列，该句不会生成猜测的投影。

下表用示意读音说明时间轴上的三种关系；具体 H/L 和音素边界取决于该句的模型输出：

| 关系 | mora 与音素 | `phone_kana` | `phone_tone` |
| --- | --- | --- | --- |
| 一拍含多个音素 | `カ(H) → k, a` | 两个区间都标 `カ` | 两个区间都标 `HH` |
| 多拍共用一个音素 | `オ(H) / ー(L) → oː` | 该区间标 `オ\|ー` | 该区间标 `HL` |
| 各拍各有音素 | `オ(H) / ー(L) → o, o` | 依次标 `オ`、`ー` | 依次标 `HH`、`LL` |

第二行的 `oː` 只有 MFA 给出的**一个**区间：`HL` 说明该区间关联的 mora 从高到低，不表示系统在区间内部找到了降调的精确时刻，也不会人为切开它。促音、拨音和长音符号同样按锁定 mora 与实际音素序列使用明确规则处理。

## 音素层上的重音标签

每个非停顿音素在 `phone_tone` 中使用以下标签：

| 标签 | 含义 |
| --- | --- |
| `HH`、`LL` | 关联 mora 的音型恒为高或低；单个 mora 也使用双字符标签 |
| `HL`、`LH` | 同一个音素覆盖的 mora 按顺序发生一次高低变化 |
| `??` | 该音素关联的所有 mora 都没有可用的词汇重音预测 |

这些标签描述 mora 的**起点与终点状态**，并不意味着一个音素一定横跨两拍。若同一音素内混合已知和未知重音，或需要表示 `HLH`、`LHL` 这类多次反转，当前双字符标签无法忠实表达，投影会失败。完整的有序 mora 信息仍保留在诊断 JSON 中。

## 输出与质量门槛

正常对齐产物是六层 Praat TextGrid。`original` 和 `kana` 分别保存整句原文与锁定读音；`words` 表示词语及停顿；`phones` 给出音素及其时间区间；`phone_kana` 与 `phone_tone` 在**同一组音素边界**上给出对应假名和重音。已发布的三个音素相关层覆盖完整时间轴；停顿或标点区间在三层保留相同的非语音标签，不携带 H/L。`alignment.json` 保留逐音素 mora 与时间信息，`mora.json` 保留词的重音解析，`postprocess.json` 保留边界和声学审核证据；正式产物还配有处理后 WAV 及音频哈希回执。

声学后处理可以根据可靠的起音、收尾声能证据微调**语音与明确停顿之间**的边界；它不会移动相邻语音音素之间的 MFA 边界，也不会在单个音素内部制造新边界。发布前会检查 TextGrid 结构、时间顺序、停顿、标点和未被对齐覆盖的持续声音。失败样本保留原因与诊断，不将缺失的 TextGrid 记作成功。

这个功能保证的是**输入读音、mora、所选音素序列和输出时间层之间的可核对关系**。通过自动检查并不等于人工确认每个音素边界或重音正确；专名、复合词、口语读法、背景声及未覆盖的模型音素组合仍可能需要读音覆盖、规则扩展或人工复核。
